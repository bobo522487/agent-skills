# Coding Standards（目录、编码、异常与测试规范）

> 本文件由 `@standards-reviewer` 与 `/code-review`（Standards 轴）读取，不占用实施阶段常驻上下文。
> 机械规则交给 `tsc` / ESLint / `dependency-cruiser`；本文件只记录需要工程判断的硬标准，由 `/retro` 持续迭代。

## 1. 项目目录规范

- 每个功能模块/包采用统一扁平结构：根文件为公开入口（反对巨型 barrel re-export），`lib/` 放私有实现，`tests/` 放同域行为测试。
- 新建文件前先查既有模块与组件变体；UI 相似需求优先扩展 `variant` / `size` / `slot`，职责完全正交时才新建。

## 2. 编码与类型规范

- **边界一次性校验**：外部输入（HTTP / CLI / 环境变量 / 文件）在入口用单一 Schema 校验收窄，内部禁止裸 `any` 或无依据 `as`。
- **互斥状态用判别联合**：判别联合类型 + `never` 穷尽检查消灭非法状态，禁止布尔 Props 爆炸。
- **零并发瀑布流**：无依赖异步操作使用 `Promise.all`；数据库查询杜绝循环 N+1，事务内严禁外部网络 IO。

## 3. 异常处理规范

- **显式错误分类**：区分可预期业务错误（结构化错误码 + 用户可读提示）与不可预期系统异常（记录上下文后向上抛出），严禁空 `catch` 吞错。
- **外部调用必设超时与降级**：所有 HTTP / RPC / 子进程调用必须显式配置超时上限。
- **前端四态闭环**：异步界面必须完整处理 Loading（防连点）/ Empty / Error（可重试）/ Normal 四态。

## 4. 测试要求

- **先红后绿（TDD）**：新增行为或修复 Bug 必须先写能复现失败的测试，再写最小实现通过。
- **两级有界验证**：单任务实施阶段仅跑本领域局部快测（`<= 30s`）；收尾统一跑受影响范围的类型、边界与集成测试。
- **只测公开契约**：测试只通过公开入口或最高层测试接缝断言可观测行为，禁止 mock 内部私有函数。
