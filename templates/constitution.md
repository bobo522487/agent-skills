# Project Constitution（项目长期工程原则）

1. **先定数据结构，再写逻辑**：动笔写分支前先敲定核心类型、状态模型或数据表结构，用结构消灭散落的条件判断。
2. **深模块优先**：复杂实现隐藏在模块子目录内，对外只暴露最小稳定入口；拒绝无策略价值的纯透传薄层。
3. **先减后加，零双轨腐化**：重构或演进旧能力时同步清理旧入口与死分支；绝不在仓库留下「同一件事的新旧两套写法」。
4. **门禁优先于文档**：凡能用静态类型、Linter、`dependency-cruiser` 或自动化测试拦截的错误，必须固化为编译/CI 红灯，不靠口头提醒。
5. **实证交付，测行为不测实现**：通过公开入口与真实运行产物（测试/脚本/真机行为）证明有效，不以「能编译」充数；内部重构不破坏测试。
6. **最小依赖与可逆决策**：无充分理由不引入新第三方库；重大不可逆架构取舍必须沉淀进 `docs/adr/`。
