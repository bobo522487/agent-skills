# SDD 单一入口

用户只发 `/sdd <任务>`。深度由 Agent 判定，用户不分级。

## 步骤

1. **读索引**：读 `AGENTS.md`、`docs/constitution.md`、`docs/pitfalls.md`；存在则读 `GLOSSARY.md` 与相关 `docs/adr/`。完成标准：能说出与本任务相关的约定和红线。
2. **定深度**：按顺序命中即停；除红线外不询问用户。
   - **红线**：不可逆或高风险操作（删数据、覆盖重要数据、`git push --force`、改系统全局环境变量、写密钥）→ 停下，说明风险与更安全的做法，等用户确认。
   - **加深**：跨文件 / 新行为 / 数据结构或 API / 权限 / 并发或状态机，任一命中 → 加深。
   - **最小**：其余 → 最小。
   完成标准：只选一条路径，并写出命中的信号。
3. **执行**：
   - 加深：输出修改计划与文件清单，随即写最小 spec（每条需求 `FR-001`…）→ 测试先行 → 实现 → 对照 spec 与测试审查；格式与追踪矩阵按 `docs/spec-template.md`。
   - 最小：查既有复用 → 最小改动 → 局部验证（`<= 30s`）。
   完成标准：加深路径每条需求都有实现位置、测试用例、验收结果；最小路径改动只落在计划文件内。
4. **汇报**：列出修改文件、跑过的验证、结果状态；严格区分「已实测通过」与「未验证」。完成标准：用户无需追问即可知道做了什么、证据在哪。

其余铁律（只读证据制审查、2 轮熔断、历史锚定与错题晋升）见 `AGENTS.md` 第 3 节，此处不重复。
