# Initialize / Upgrade Minimal SDD Repo (`sdd-init`)

Scaffold or upgrade the repository using the sibling `./templates/` files beside this `SKILL.md`. Never overwrite user customizations. This skill is also the intended handler when a user says “`/sdd init`” in a project folder.

## Managed files and version marker

- `AGENTS.md` at repo root
- `docs/constitution.md`
- `docs/pitfalls.md`
- `docs/spec-template.md`

Every managed template starts with one marker line:

`<!-- sdd-init-template-version:V sha256:<hash> -->`

`V` is the template version; `<hash>` is the SHA-256 of the body **after** the marker line. `current` is the `version` in this skill's frontmatter (currently `1`); every bundled template's marker `V` must equal it. The marker is the preferred source of truth for “was this generated by sdd-init, and is it still pristine”. For installs made before markers existed, the bundled marker hashes are also the hashes of the old whole-file templates, and are used as known legacy hashes.

## Steps

1. Inspect `AGENTS.md`, `GLOSSARY.md`, `docs/`, and `tsconfig.json`. For each managed target, look for a marker line anywhere in the file (not only the first line).
2. Determine the state of each managed target:
   - **Missing** → create it from the sibling template; record as `新建`.
   - **Marker present, version < `current`, body hash matches marker hash** → replace the managed body with the current template (including its new marker); record as `升级`.
   - **Marker present, version == `current`, body hash matches** → leave untouched; record as `已是最新`.
   - **Marker absent, whole-file hash equals a known legacy hash** → this is a pristine install from before markers existed; replace it with the current template; record as `升级`.
   - **Marker version > `current`, marker absent with no legacy-hash match, or body hash mismatch** → leave untouched, never overwrite; record as `保留（需人工合并）` and list the path in the summary.
3. For `constitution.md`, `pitfalls.md`, and `spec-template.md`, apply the same state rule under `docs/`. Only create/upgrade files in `docs/`; never touch `docs/adr/` or other user files.
4. If `docs/agents/` is not configured yet, guide the user through `/setup-matt-pocock-skills`.
5. If `tsconfig.json` exists and `.dependency-cruiser.cjs` is absent, ask once whether to run `/setup-ts-deep-modules`.
6. End with a short audit summary containing three lists: `新建`, `升级`, `保留（需人工合并）`. State `已是最新` only when every managed target is `已是最新` and the `保留` list is empty; never state `已是最新` while any file is retained. Do not report a retained customized file as upgraded.

Records of user edits must survive: any file whose hash no longer matches is user-owned.
